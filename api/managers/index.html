Managers¶

Los managers son el punto de entrada principal de util_bbdd. Proveen la API de alto nivel para operaciones sobre bases de datos.

Los dos comparten los nombres del ciclo de vida: init(), get_connection(), release_connection() y close() (en el async son corrutinas). SyncDatabaseManager.close_connection() se retiró en 1.0.0; ver Migración a la API 1.0.

SyncDatabaseManager¶

Manager sincrónico para operaciones de base de datos. Soporta todos los motores (MariaDB, MySQL, PostgreSQL, Oracle, SQLite, SQL Server, HSQLDB). Referencia curada: Manager Síncrono.

SyncDatabaseManager(db_type, conn_params, queries_file=None, use_pool=True) ¶

Bases: SyncCatalogFacade, DatabaseManagerSharedMixin

Clase para manejar conexiones y operaciones de base de datos.

Soporta logging y manejo de excepciones propias. Bases de datos soportadas: MariaDB, MySQL, Oracle, PostgreSQL, SQLite, HSQLDB, SQL Server

Devuelve el manager inicializado (simetría con AsyncDatabaseManager.init()).

El manager sync conecta en __init__, así que no hace I/O: existe para que el mismo código de arranque sirva en sync y async. Es idempotente.

execute_custom_many(sql, params=None, timeout=None, *, read_only=False, max_rows=None) ¶

Ejecuta una consulta SQL personalizada y retorna múltiples filas.

Parameters:

Name Type Description Default
sql str

Consulta SQL a ejecutar.

 required
params dict[str, Any] | None

Diccionario de parámetros SQL (opcional).

 None
timeout float | None

Timeout en segundos (opcional).

 None
read_only bool

Si True (v4.6.0, G19 de util_bbdd_web), la consulta va en una transacción de solo lectura del motor que termina siempre en rollback: una escritura falla en el motor (SET TRANSACTION READ ONLY en PostgreSQL y Oracle, START TRANSACTION READ ONLY en MySQL/MariaDB, PRAGMA query_only en SQLite, SET SESSION CHARACTERISTICS … READ ONLY en HSQLDB). SQL Server no tiene transacciones de solo lectura: la consulta va en una transacción explícita que se deshace al terminar.

 False
max_rows int | None

Como mucho estas filas (fetchmany; v4.6.0, G20): el resto no llega a memoria. Para saber si había más, pide n + 1. None (default): todas.

 None

Returns:

Type Description
Rows

Lista de filas resultantes.

Raises:

Type Description
DatabaseOperationError

Si falla la ejecución (el error del driver queda en __cause__); también una escritura con read_only=True.
QueryTimeoutError

Si se supera timeout.
ValueError

Si max_rows no es un entero ≥ 1.

Examples:

Ejecutar una query personalizada:

>>> from util_bbdd import SyncDatabaseManager
>>> manager = SyncDatabaseManager(
...     db_type="postgresql",
...     conn_params={
...         "host": "localhost",
...         "port": 5432,
...         "user": "postgres",
...         "password": "secret",
...         "database": "mydb"
...     }
... )
>>> # Query simple sin parámetros
>>> result = manager.execute_custom_many("SELECT * FROM users LIMIT 5")
>>> print(f"Encontradas {len(result)} filas")
>>> # Query con parámetros
>>> result = manager.execute_custom_many(
...     "SELECT * FROM users WHERE age > :age",
...     params={"age": 18}
... )
>>> manager.close()

execute_custom_result(sql, params=None, timeout=None, *, read_only=False, max_rows=None) ¶

Ejecuta una consulta SQL personalizada y devuelve sus columnas y filas (5.0.0, G42 de util_bbdd_web).

Como :meth:execute_custom_many, que no cambia, pero con los nombres de columna: también sin filas y con nombres repetidos, en el orden del SELECT.

Parameters:

Name Type Description Default
sql str

Consulta SQL a ejecutar.

 required
params dict[str, Any] | None

Diccionario de parámetros SQL (opcional).

 None
timeout float | None

Plazo en segundos (opcional), comprobado en el cliente. Con read_only=True en PostgreSQL también corta la consulta en el servidor (SET LOCAL statement_timeout, D8-4); en el resto de motores la consulta sigue en el servidor hasta terminar.

 None
read_only bool

Como en :meth:execute_custom_many (transacción de solo lectura que termina en rollback).

 False
max_rows int | None

Como en :meth:execute_custom_many (fetchmany; para saber si había más, pide n + 1).

 None

Returns:

Type Description
CustomQueryResult

CustomQueryResult con columns (tupla de nombres; vacía si la sentencia no devuelve un conjunto de
CustomQueryResult

resultados) y rows.

Raises:

Type Description
DatabaseOperationError

Si falla la ejecución (el error del driver queda en __cause__); también una escritura con read_only=True.
QueryTimeoutError

Si se supera timeout (en PostgreSQL con read_only, también en el servidor; el error del driver queda en __cause__).
ValueError

Si max_rows no es un entero ≥ 1.

Examples:

>>> result = manager.execute_custom_result(
...     "SELECT id, nombre FROM clientes WHERE alta > :desde",
...     params={"desde": "2026-01-01"},
...     timeout=30,
...     read_only=True,
...     max_rows=101,
... )
>>> result.columns
('id', 'nombre')
>>> truncated = len(result.rows) > 100

get_schema_metadata(schema=None, *, kinds=ALL_KINDS, tables=None) ¶

Metadatos de un schema con una consulta por tipo de objeto (tablas, columnas, claves, índices, routines…).

Sustituye a recorrer el schema con get_columns(t), get_indices(t)…: con 500 tablas en PostgreSQL, 12 consultas en lugar de 2503 (ADR-003).

Parameters:

Name Type Description Default
schema str | None

Schema, owner o base de datos; por defecto el contexto de metadatos del manager (main en SQLite).

 None
kinds Collection[Kind]

Tipos de objeto a leer; pedir después uno no leído lanza KindNotLoadedError.

 ALL_KINDS
tables Collection[str] | None

Limita la lectura a estas tablas (hasta 50; con más, se lee el schema completo).

 None

Returns:

Type Description

SchemaSnapshot inmutable con modelos neutros (TableMeta, ColumnMeta, ForeignKeyMeta…).

Examples:

>>> [(fk.table, fk.ref_table) for fk in snapshot.all_foreign_keys()]

Raises:

Type Description
