Conexiones¶

util_bbdd.connection normaliza los parámetros de conexión (build_conn_params) y crea conexiones y pools por motor (ConnectionFactory); util_bbdd.factory añade los pools (PoolFactory) y los engines SQLAlchemy. Referencia curada: Factory de Conexiones.

param_kinds(db_type) staticmethod ¶

Clase de cada parámetro de conexión de db_type (v4.6.0, G12 de util_bbdd_web).

Sale de connection_params.kinds de database_types.json, que cubre todos los parámetros declarados (los mismos que :meth:allowed_keys). Clases (:data:ParamKind):

  • secret: credencial (password). No debe mostrarse ni guardarse en claro.
  • host: destino de red (host; dsn en Oracle, jdbc_url en HSQLDB).
  • port: puerto de red.
  • path: ruta del sistema de ficheros (certificados, socket, Instant Client, JAR; database en SQLite).
  • blocked: ejecuta SQL arbitrario al conectar (init_command); una aplicación que deja a sus usuarios configurar conexiones no debería aceptarlo.
  • plain: el resto.

Parameters:

Name Type Description Default
db_type str

Tipo de motor.

 required

Raises:

Type Description
InvalidDatabaseType

Si el motor no está soportado.
Example

ConnectionParamsManager.param_kinds("postgresql")["password"] 'secret'

redact_secrets(db_type, conn_params) staticmethod ¶

Copia de conn_params con los secretos enmascarados (v4.6.0, G11 de util_bbdd_web).

Sustituye por :data:REDACTED el valor no vacío de cada parámetro de clase secret (:meth:param_kinds) y, dentro de un valor dict (p. ej. connection_properties de HSQLDB, propiedades JDBC), el de cada clave que contenga password. El resto se copia tal cual; conn_params no se modifica.

Capacidades y drivers por motor (v4.6.0)¶

get_engine_capabilities(db_type) dice qué operaciones admite un motor y get_driver_status(db_type) qué drivers de Python están instalados (sin importarlos). Las dos se importan desde util_bbdd.connection.

Parameters:

Name Type Description Default

Tipo de motor de la librería, sin distinguir mayúsculas ni espacios alrededor.

 required
Example

EngineCapabilities(db_type, async_supported, migrate_source, migrate_target, readiness, documentation, graphs, compare, dump, dump_constraints, bulk) dataclass ¶

Qué operaciones de util_bbdd admite un motor (v4.6.0, G5 de util_bbdd_web).

Es una tabla declarativa: core es Foundation y no importa los módulos que implementan cada operación. tests/unit/connection/test_engine_capability_matrix.py la contrasta con cada fuente (MigrationPlanner, EngineReadinessAdvisor, el registro de dialectos de catálogo, dump y la fábrica de SQLAlchemy), así que un cambio de soporte que no se refleje aquí hace fallar los tests.

Attributes:

Name Type Description
db_type str

Tipo de motor de la librería ("sqlserver", no "mssql").
async_supported bool

AsyncDatabaseManager (:data:DB_ASYNC_CAPABILITIES).
migrate_source bool

Origen de MigrationPlanner (MigrationPlanner.supported_sources()).
migrate_target bool

Destino de MigrationPlanner (MigrationPlanner.supported_targets()).
readiness bool

EngineReadinessAdvisor tiene comprobaciones del motor (assess(...).supported).
documentation bool

DatabaseDocumentation (hay dialecto de catálogo).
graphs bool

Grafos de relaciones de analysis (hay dialecto de catálogo).
compare bool

SchemaComparator (compara Inspector de SQLAlchemy: hace falta dialecto de SQLAlchemy).
dump bool

DumpOrchestrator como origen o destino (engines de SQLAlchemy).
dump_constraints bool

El volcado desactiva y reactiva las constraints del destino (DumpConfig); en el resto de motores con dump carga sin tocarlas.
bulk bool

BulkCrud y ParallelBulkLoader (engine de SQLAlchemy).
