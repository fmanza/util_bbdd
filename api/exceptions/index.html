Excepciones¶

Jerarquía unificada de excepciones de util_bbdd. Todas heredan de DatabaseException.

Se importan desde el módulo público util_bbdd.exceptions (v0.43.0); la raíz util_bbdd exporta solo DatabaseException. Ver Migración a la API 1.0.

Auditoría de bulk (v0.18.0)

AuditError y sus subclases se importan de util_bbdd.exceptions (también AuditError de util_bbdd.bulk); desde 1.0.0 ya no de la raíz util_bbdd. Como heredan de DatabaseException, un except DatabaseException alrededor de operaciones bulk captura también los errores de auditoría (solo se lanzan al configurar o leer el CSV y, con AuditOptions(strict=True), al no poder escribirlo).

Desde v0.29.0 los lanza el módulo común util_bbdd.audit; la jerarquía y los imports no cambian. Con AuditOptions(strict=True), un fallo de un AuditOptions.sink llega como OSError o AuditError; cualquier otra excepción del destino se envuelve en AuditError.

Carga paralela desde BulkCrud (v3.0.0)

ParallelLoadError la lanza BulkCrud.bulk_*_from_df con parallel=ParallelOptions(...) cuando falla alguna partición. Las demás particiones quedan confirmadas: exc.result (un ParallelLoadResult) dice cuántas filas se cargaron y qué particiones fallaron. ParallelBulkLoader no la lanza: devuelve los errores en partition_errors.

Reconstrucción de índices únicos (v3.3.0)

IndexRebuildError la lanzan BulkCrud.maintenance_scope(disable_indexes="all") y ParallelBulkLoader.load() con ParallelOptions(disable_indexes="all") cuando un índice único o una PK no se puede reconstruir al terminar la carga, casi siempre por claves duplicadas. Se lanza después de restaurar todo lo demás: exc.results tiene un IndexActionResult por índice y exc.duplicates, hasta 5 claves repetidas por índice (vacío en SQL Server dentro de bulk_session, donde el propio servidor deshace la transacción al fallar). exc.recovery_ddl (desde 4.0.0) tiene, por índice (único o no) o FK que se borró para la carga y no se pudo recrear (PostgreSQL, MariaDB/MySQL InnoDB e índices únicos sin constraint de Oracle), el DDL para recrearlo a mano. Los índices únicos de expresión de PostgreSQL (lower(email)) cuentan igual que el resto.

Capturar errores genéricamente

Para capturar cualquier error de util_bbdd, usa except DatabaseException. Para errores específicos, captura la subclase correspondiente antes.

exceptions ¶

Jerarquía pública de excepciones de util_bbdd.

Punto de importación estable de todas las excepciones de la librería (API 1.0). La implementación vive en util_bbdd._core.exceptions; este módulo solo la reexporta. Todas heredan de :class:DatabaseException, la única que se exporta también desde la raíz util_bbdd.

Examples:

>>> from util_bbdd.exceptions import DatabaseException, QueryNotFoundError
>>> issubclass(QueryNotFoundError, DatabaseException)
True

DumpReportError(message, *, output_path=None) ¶

Bases: DumpError

Error generando el informe Excel de auditoría del volcado.

Cuando la lanza DumpOrchestrator.run(), la carga ya ha terminado: result conserva el DumpResult completo (tablas, constraints, PK sync, auditoría) para que el llamador no lo pierda. Su report es la ruta prevista del informe, que no llegó a crearse.

Attributes:

Name Type Description
output_path Path | None

Ruta prevista del informe, o None si falló antes de calcularla.
result Any

DumpResult del volcado, o None si el error no viene de run(). Tipado como Any porque _core no puede importar de dump (capas de docs/architecture.md).

Examples:

>>> try:
...     result = DumpOrchestrator(config).run()
... except DumpReportError as exc:
...     result = exc.result  # la carga se completó; solo falta el Excel

IndexRebuildError(message, *, results=None, duplicates=None, recovery_ddl=None) ¶

Bases: DatabaseOperationError

No se pudo reconstruir un índice único o una PK desactivados con disable_indexes="all" (v3.3.0).

Casi siempre porque la carga trajo claves duplicadas: con "all" la unicidad no se comprueba durante la carga y la reconstrucción es la última comprobación. Se lanza después de intentar restaurar todo (los demás índices, las FK entrantes y las constraints). En PostgreSQL y SQL Server, dentro de bulk_session, la excepción deshace la sesión entera (carga y DDL); en Oracle y MariaDB/MySQL el DDL ya confirmó y las filas quedan cargadas.

Attributes:

Name Type Description
results Any

IndexActionResult de todos los índices (action="failed" en los que no se reconstruyeron).
duplicates dict[str, list[str]]

Por índice que falló, hasta 5 claves duplicadas encontradas (texto "valores → repeticiones").
recovery_ddl dict[str, str]

Por índice (único o no) o FK que se borró para la carga y no se pudo recrear (PostgreSQL, MariaDB/MySQL InnoDB y, desde 4.0.0, índices únicos sin constraint de Oracle), el DDL para recrearlo a mano una vez quitados los duplicados.

Examples:

>>> try:
...     with crud.bulk_session(), crud.maintenance_scope("ventas", disable_indexes="all"):
...         crud.bulk_insert_from_df(df, "ventas", generar_sql=False)
... except IndexRebuildError as exc:
...     print(exc.duplicates)

ParallelLoadError(message, *, result=None) ¶

Bases: DatabaseOperationError

Alguna partición de una carga paralela de BulkCrud falló (v3.0.0, ParallelOptions).

La carga paralela no es atómica: las particiones que terminaron bien quedan confirmadas. result es el ParallelLoadResult (filas por partición, errores, contadores de auditoría) para decidir qué reintentar.

Attributes:

Name Type Description
result Any

ParallelLoadResult de la carga. Tipado como Any porque _core no puede importar de bulk.

Examples:

>>> try:
...     crud.bulk_insert_from_df(df, "ventas", generar_sql=False)
... except ParallelLoadError as exc:
...     fallidas = [pr.index for pr in exc.result.partition_results if pr.error]
