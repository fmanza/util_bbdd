Ejemplo: Volcado de Datos entre Motores¶

1. Contexto del Ejemplo¶

Copia todos los datos de un esquema PostgreSQL a un esquema SQL Server respetando automáticamente el orden de las FKs, limpiando el destino antes de cargar y generando un informe Excel de auditoría.

Resuelve el caso de actualizar un entorno de analítica con datos de producción (full refresh): tablas, FKs, columnas omitidas y errores quedan documentados en el informe Excel al finalizar.

2. Implementación de Referencia¶

"""Ejemplo: Volcar datos de PostgreSQL a SQL Server con DumpOrchestrator.

Los engines se crean con las URL de SQLAlchemy de las variables de entorno UTIL_BBDD_EXAMPLE_SOURCE_URL (p. ej.
``postgresql+psycopg://user:password@prod-server:5432/production_db``) y UTIL_BBDD_EXAMPLE_TARGET_URL (p. ej.
``mssql+pymssql://user:password@analytics-server/analytics_db``); los schemas, de UTIL_BBDD_EXAMPLE_SOURCE_SCHEMA
(``public`` por defecto) y UTIL_BBDD_EXAMPLE_TARGET_SCHEMA (``dbo`` por defecto). Las tablas deben existir ya en el
destino: el volcado copia datos, no DDL. Sin las dos URL, el ejemplo termina explicando cómo configurarlas.

Uso:
    python dump_data_export.py
"""

import os

from pathlib import Path

from sqlalchemy import create_engine

from util_bbdd.dump import DumpConfig, DumpOrchestrator


def main() -> None:
    source_url = os.environ.get("UTIL_BBDD_EXAMPLE_SOURCE_URL")
    target_url = os.environ.get("UTIL_BBDD_EXAMPLE_TARGET_URL")
    if not (source_url and target_url):
        print("Define UTIL_BBDD_EXAMPLE_SOURCE_URL y UTIL_BBDD_EXAMPLE_TARGET_URL con las URL SQLAlchemy, p. ej.")
        print("postgresql+psycopg://user:password@prod-server:5432/production_db  (origen, psycopg 3)")
        print("mssql+pymssql://user:password@analytics-server/analytics_db        (destino)")
        return

    # 1. Engines
    src_engine = create_engine(source_url)
    dst_engine = create_engine(target_url)
    try:
        # 2. Configuración
        config = DumpConfig(
            source_engine=src_engine,
            target_engine=dst_engine,
            source_schema=os.environ.get("UTIL_BBDD_EXAMPLE_SOURCE_SCHEMA", "public"),
            target_schema=os.environ.get("UTIL_BBDD_EXAMPLE_TARGET_SCHEMA", "dbo"),
            chunk_size=1_000,
            output_dir=Path("reports"),
            truncate_target=True,
        )

        # 3. Ejecutar volcado
        result = DumpOrchestrator(config).run()

        # 4. Revisar resultado
        print(f"Informe: {result.report}")
        print(f"Orden de carga: {result.load_order}")

        for tr in result.table_results:
            print(
                f"  [{tr.status.upper():15}] {tr.table_name:30} "
                f"origen={tr.source_rows:>8}  destino={tr.target_rows_after:>8}"
            )
            if tr.error_msg:
                print(f"    ERROR: {tr.error_msg}")
    finally:
        src_engine.dispose()
        dst_engine.dispose()


if __name__ == "__main__":
    main()

3. Explicación del Código¶

Aspectos críticos:

  • DumpConfig.chunk_size: filas por lectura del origen (default 5000; el ejemplo usa 1000). En destinos MariaDB/MySQL con filas grandes (TEXT/JSON), reducirlo si un lote supera max_allowed_packet.
  • truncate_target=True: vacía el destino antes de cargar en orden inverso topológico (respetando FKs). Con False, los datos se añaden al existente (modo append); riesgo de duplicados si las PKs ya existen.
  • SyncDatabaseManager.get_sqlalchemy_engine(): para destino MariaDB, usar este método en lugar de create_engine() directamente, ya que incluye automáticamente pool_pre_ping=True y pool_recycle=3600 para evitar Server has gone away.
  • Best-effort: un fallo en una tabla no detiene el volcado. Revisar el informe Excel para identificar las tablas con ERROR o MISSING_TARGET.
# Volcado cross-engine con SyncDatabaseManager (MariaDB destino)
from util_bbdd.managers import SyncDatabaseManager
from util_bbdd.dump import DumpConfig, DumpOrchestrator
from pathlib import Path

dst_mgr = SyncDatabaseManager("mariadb", {
    "host": "replica-server", "user": "writer",
    "password": "secret", "database": "replica_db",
})
config = DumpConfig(
    source_engine=src_engine,
    target_engine=dst_mgr.get_sqlalchemy_engine(),  # pool_pre_ping incluido
    chunk_size=500,
    output_dir=Path("reports"),
)

4. Ejecución y Pruebas¶

# Validación sintáctica
python -m py_compile docs/examples/dump_data_export.py

# Ejecución: origen y destino accesibles, con las tablas ya creadas en el destino
# (sin las dos URL explica cómo configurarlas)
export UTIL_BBDD_EXAMPLE_SOURCE_URL="postgresql+psycopg://user:password@prod-server:5432/production_db"
export UTIL_BBDD_EXAMPLE_TARGET_URL="mssql+pymssql://user:password@analytics-server/analytics_db"
# opcionales: UTIL_BBDD_EXAMPLE_SOURCE_SCHEMA (public) y UTIL_BBDD_EXAMPLE_TARGET_SCHEMA (dbo)
python docs/examples/dump_data_export.py

El informe Excel reports/dump_report_<timestamp>.xlsx contiene hojas de Auditoría Tablas, Tablas Faltantes y Columnas Inexistentes, y, si aplican, Índices (con manage_indexes=True), Auditoría Bulk (con bulk_audit_path) Secuencias PK (con sync_pk_sequences=True, el valor por defecto) y Errores de Reactivación (si falla la reactivación general de constraints). La última hoja, Condiciones del motor, recoge siempre la verificación de EngineReadinessAdvisor del origen y del destino.
