Guía de Configuración de Drivers de Bases de Datos¶

Descripción General¶

Esta guía cubre la selección y configuración de drivers para cada base de datos soportada en util_bbdd, con énfasis en los requisitos únicos de Oracle y sus limitaciones de compatibilidad.

Oracle: Requisitos de la Librería Cliente¶

Introducción¶

Oracle se conecta con python-oracledb (extra oracle, oracledb>=26). util_bbdd soporta sus dos modos:

  • Thin Mode (predeterminado): Python puro, sin Oracle Instant Client; managers sync y async; Oracle 12.1 en adelante
  • Thick Mode (oracle_thick_mode=True): requiere Oracle Instant Client; solo managers sync; necesario para Oracle 11g

Thin Mode¶

Recomendado para: - Cualquier uso con Oracle 12.1 o posterior, sync o async - Entornos donde Instant Client no está disponible

Configuración: 

from util_bbdd import AsyncDatabaseManager

manager = AsyncDatabaseManager(
    db_type="oracle",
    conn_params={
        "user": "scott",
        "password": "tiger",
        "dsn": "oracle-host:1521/ORCL",
        "oracle_thick_mode": False,  # Predeterminado; explícito para claridad
    },
)

# Funciona con async/await
snapshot = await manager.get_schema_metadata()

Con SyncDatabaseManager es igual (sin await): thin es el modo por defecto también en sync.

Limitaciones: - Sin soporte para Oracle 11g: el modo thin de python-oracledb conecta con Oracle 12.1 o posterior

Thick Mode¶

Recomendado para: - Soporte de Oracle 11g (requerido) - Cargas de trabajo sincrónicas - Aplicaciones que necesitan características completas del cliente Oracle

Requisitos: 1. Oracle Instant Client compatible con la versión de la base de datos (para 11g, un cliente que conecte con 11.2; consultar la matriz de interoperabilidad cliente/servidor de Oracle) 2. python-oracledb (extra oracle) 3. Solo código sincrónico: con thick mode inicializado en el proceso, las conexiones async de Oracle fallan con ConnectionError

Instalación¶

  1. Descargar Oracle Instant Client:
  2. Visita Descargas de Oracle Instant Client
  3. Selecciona tu SO (Linux, Windows, macOS)

  4. Descarga el paquete "Basic" para tu arquitectura (x86_64, ARM64, etc.)

  5. Extrae el paquete: 

    # Linux / macOS
mkdir -p ~/oracle/instantclient_19_x
unzip instantclient-basic-linux.x64-19.*.zip -d ~/oracle/

# Windows
REM Extrae a C:\oracle\instantclient_19_x

  6. Configura la ruta de la librería (solo Linux/macOS): 

    export LD_LIBRARY_PATH=$HOME/oracle/instantclient_19_x:$LD_LIBRARY_PATH

Desde la versión 26 de python-oracledb (mínimo de util_bbdd desde 4.0.0), en Linux y macOS el modo thick busca la librería por su nombre sin versión (libclntsh.so o libclntsh.dylib): si el Instant Client solo trae el nombre versionado (libclntsh.so.19.1), crea el enlace (ln -s libclntsh.so.19.1 libclntsh.so) en su directorio.

  1. python-oracledb: instálalo con el extra oracle (pip install "util_bbdd[oracle] @ git+https://github.com/fmanza/util_bbdd.git@v5.2.0") o con pip install oracledb.

Configuración¶

Activa thick mode estableciendo oracle_thick_mode=True y proporcionando la ruta del cliente:

from util_bbdd import SyncDatabaseManager

# Uso sincrónico
manager = SyncDatabaseManager(
    db_type="oracle",
    conn_params={
        "user": "scott",
        "password": "tiger",
        "service_name": "ORCL",  # Usa service_name para 11g
        "oracle_thick_mode": True,
        "oracle_client_path": "/home/user/oracle/instantclient_19_x",
    },
)

# Funciona con código sincrónico (no-async)
snapshot = manager.get_schema_metadata()

Parámetros: - oracle_thick_mode (bool, predeterminado=False): Habilita thick mode - oracle_client_path (str): Ruta al directorio de Oracle Instant Client (requerido si oracle_thick_mode=True)

Identificadores de Conexión: además de user y password, uno de service_name, sid, dsn o database (con host y port salvo con dsn): 

conn_params = {"user": "scott", "password": "tiger", "host": "oracle-host", "service_name": "ORCL"}
conn_params = {"user": "scott", "password": "tiger", "host": "oracle-host", "sid": "ORCL"}
conn_params = {"user": "scott", "password": "tiger", "dsn": "oracle-host:1521/ORCL"}

Seguridad de Hilos¶

La inicialización de thick mode es segura para hilos mediante bloqueo interno: - La primera llamada a init_oracle_thick_mode() tiene éxito y bloquea el modo - Las llamadas posteriores desde otros hilos se devuelven sin re-inicializar - Con thick mode ya inicializado, una conexión async de Oracle en el mismo proceso lanza ConnectionError

Ejemplo (multi-hilo): 

import threading
from util_bbdd import SyncDatabaseManager

def init_oracle(thread_id):
    try:
        manager = SyncDatabaseManager(
            db_type="oracle",
            conn_params={
                "user": "scott",
                "service_name": "ORCL",
                "oracle_thick_mode": True,
                "oracle_client_path": "/ruta/a/instant/client",
            },
        )
        print(f"Hilo {thread_id}: OK")
    except Exception as e:
        print(f"Hilo {thread_id}: Error - {e}")

# Seguro llamar desde múltiples hilos
threads = [
    threading.Thread(target=init_oracle, args=(i,))
    for i in range(5)
]
for t in threads:
    t.start()
for t in threads:
    t.join()

Resolución de Problemas¶

Error Causa Solución
DPI-1047: Cannot locate a 32-bit Oracle Client Arquitectura incorrecta Descarga Instant Client que coincida con tu intérprete Python (64-bit para x86_64, etc.)
ORA-00000: Oracle client library initialization failed Instant Client no encontrado Verifica que oracle_client_path apunte al directorio de Instant Client extraído
ConnectionError: El modo asincrónico de Oracle no es compatible con thick mode en el mismo proceso Conexión async en un proceso que ya inicializó thick mode Usar el manager sync, o thin mode (sin oracle_thick_mode) en todo el proceso
ORA-12154: TNS:could not resolve the connect identifier Nombre de servicio inválido Verifica el nombre del servicio de base de datos y la configuración de red

Oracle: Selección de Catálogo Consciente de la Versión¶

util_bbdd detecta automáticamente la versión de Oracle y carga el dialecto apropiado:

  • Oracle 11g (11.2.x): Usa Oracle11Catalog (omite soporte de columnas IDENTITY)
  • Oracle 12c y posterior: Usa OracleCatalog (soporte completo de columnas IDENTITY)

Esta detección es perezosa (ocurre en la primera consulta de metadatos) y cacheada (una sola llamada por conexión).

Cómo Funciona¶

  1. Primera consulta de metadatos desencadena la detección de versión
  2. SQL de versión se ejecuta: SELECT version FROM product_component_version WHERE product LIKE 'Oracle Database%' AND ROWNUM = 1
  3. Selección de dialecto: Si versión < 12.0, usa Oracle11Catalog; si no, OracleCatalog
  4. Cacheado para toda la duración de la conexión

No se requieren consultas adicionales ni configuración manual.

Otras Bases de Datos¶

PostgreSQL¶

Driver: psycopg (v3) + psycopg-pool (sync) y asyncpg (async). psycopg2 no lo usan los managers; solo sirve para Engines propios postgresql+psycopg2:// (p. ej. la estrategia execute_values de bulk).

Instalación: 

pip install "util_bbdd[postgresql] @ git+https://github.com/fmanza/util_bbdd.git@v5.2.0"  # psycopg[binary], psycopg-pool y asyncpg

Configuración: 

from util_bbdd import SyncDatabaseManager

manager = SyncDatabaseManager(
    db_type="postgresql",
    conn_params={
        "user": "postgres",
        "password": "contraseña",
        "host": "localhost",
        "port": 5432,
        "database": "mibd",
    },
)

MySQL / MariaDB¶

Desde v0.19.0 son dos motores distintos, con las mismas claves de conn_params:

db_type Driver sync Driver async Instalación
mariadb mariadb (MariaDB Connector/Python) aiomysql extra mariadb
mysql pymysql aiomysql extra mysql

Instalación de un extra: pip install "util_bbdd[mariadb] @ git+https://github.com/fmanza/util_bbdd.git@v5.2.0".

Limitación del driver (MariaDB): MariaDB Connector/Python no tiene ssl_verify_identity. Con ssl_ca verifica la CA y el hostname a la vez, sin forma de verificar solo la CA: el nombre o la IP con que conectas debe figurar en el certificado del servidor. Ver TLS en MariaDB. Con db_type="mysql" (PyMySQL) sí existe ssl_verify_identity.

Configuración: 

from util_bbdd import SyncDatabaseManager

manager = SyncDatabaseManager(
    db_type="mysql",
    conn_params={
        "user": "root",
        "password": "contraseña",
        "host": "localhost",
        "port": 3306,
        "database": "mibd",
    },
)

SQL Server¶

Driver: pymssql (sync, por defecto) o pyodbc (sync, con sql_server_driver="pyodbc"); aioodbc en async. pyodbc y aioodbc necesitan el Microsoft ODBC Driver for SQL Server del sistema operativo.

Instalación: 

pip install pyodbc aioodbc
# o, solo sync
pip install pymssql

Configuración: 

from util_bbdd import SyncDatabaseManager

manager = SyncDatabaseManager(
    db_type="sqlserver",
    conn_params={
        "user": "sa",
        "password": "contraseña",
        "host": "localhost",
        "port": 1433,
        "database": "mibd",
        "sql_server_driver": "pyodbc",
        "driver_name": "ODBC Driver 17 for SQL Server",  # solo pyodbc
    },
)

Limitación del driver (pymssql): trust_cert no tiene efecto con pymssql, porque la validación del certificado depende de FreeTDS (freetds.conf) y no de la conexión. Desde v0.39.2 la librería avisa con un WARNING una vez por servidor y proceso. Para controlarla por conexión, usa pyodbc o aioodbc. Ver TLS en SQL Server.

SQLite¶

Driver: sqlite3 integrado

Configuración: 

from util_bbdd import SyncDatabaseManager

manager = SyncDatabaseManager(
    db_type="sqlite",
    conn_params={
        "database": "/ruta/a/base_de_datos.db",
    },
)
